## 事前条件

- QA以外のDB/Media/Productionを使用しない。
- OWNER、Tenant MEMBER、Map EDITOR、Spot Editor、別Tenant Userのfixtureを識別する。
- 公開前後のSpot値、Media、release ID、Analytics件数を控える。
- Resend/R2/custom domainが未設定の場合、fake email/local Snapshot/既存Quick Tunnelを使い、live integrationはPENDINGと記録する。

## 1. Auth / RBAC（WU-23 / KAN-56）

- [ ] OWNERが組織招待を作成し、発行直後のURLだけを取得できる。通常一覧にraw tokenが残らない。
- [ ] revoke済み、期限切れ、使用済み、別メールでの招待acceptが拒否される。
- [ ] 既存User acceptでpasswordが変わらずMEMBERになり、新規User acceptでUser+MEMBERが作成される。
- [ ] Map EDITOR/Spot Editorは組織招待を作成できない。
- [ ] password reset/changeで旧sessionと現在sessionが無効になり、再loginが必要になる。
- [ ] membership削除/role変更/global disable後の旧session権限が失効する。他Tenant membershipは残る。
- [ ] 最終OWNER削除guardとcross-Tenant denialを確認する。

## 2. Spot Editor / Revision（WU-24 / KAN-53）

- [ ] OWNERが既存MEMBERをSpot Editorへassignできる。Map EDITORは割当Map内の既存MEMBERだけをassignできる。
- [ ] Spot inviteを既存MEMBER、既存User非MEMBER、新規Userでacceptし、Tenant/Spot tamperingが拒否される。
- [ ] Spot Editorには担当Spotと許可フィールド/現在写真だけが表示され、Category/PIN/座標/公開/Map/Floor/Decoration/Media Library/他Spotは操作できない。
- [ ] 保存すると「承認待ち」になり、live/public/Snapshotは旧値のまま。
- [ ] OWNERまたは担当Map EDITORがdiffを確認しApprove/Rejectでき、Spot Editor自身はreviewできない。
- [ ] Approveは許可フィールドと写真順だけを原子的に反映し、Rejectはliveを変えない。
- [ ] live変更後のstale approveはconflictになり、自動merge/force approveされない。
- [ ] assignee replacementで旧担当アクセスが即時失効し、旧pendingが解決するまで新担当は新規pendingを作れない。
- [ ] pending uploadはGC対象外、Reject後のzero-reference assetは通常GC候補になる。

## 3. Audit（WU-25 / KAN-54）

- [ ] OWNERの監査一覧でinvite/member/Map role/Spot Editor/revision/publish/deleteの代表eventを時刻・actor・target付きで確認する。
- [ ] Map EDITOR、Spot Editor、別Tenant OWNERは対象Tenantの監査一覧を読めない。
- [ ] token、password、cookie、email body、request bodyがmetadataへ含まれない。

## 4. Transactional Email（WU-26 / KAN-69）

- [ ] 組織招待、Spot招待、reset、signup verificationの日本語メールと正しい固定リンクをfake/localで確認する。
- [ ] 配送履歴にpurpose/recipient/status/attempt/provider IDまたはsanitized errorだけがあり、raw URL/body/tokenがない。
- [ ] Resendが設定済みなら実配送を1件ずつ確認する。未設定なら`EXTERNAL ACTIVATION PENDING`とする。

## 5. Security（WU-27 / KAN-66）

- [ ] login 5/15分、reset 5/60分、invite accept 10/15分、signup 5/時の境界で429/Retry-Afterを確認する。
- [ ] reset/signupのgeneric responseからaccount存在を判定できない。
- [ ] cross-Origin cookie mutation、cross-Tenant Map/Spot/Category/Media/field/Decoration、未割当Map Editor、Spot Editor forbidden APIが拒否される。
- [ ] PNG/JPEG以外、偽MIME、拡張子不一致、10MiB超、path traversal相当filenameをuploadできない。
- [ ] production相当応答のCSP/nosniff/referrer/frame/permissions/HSTSとSecure/HttpOnly/SameSite cookieを確認する。

## 6. Observability / Backup（WU-28 KAN-67 / WU-29 KAN-65）

- [ ] `/api/health`はDB詳細なしでlivenessを返し、`/api/ready`はDB依存状態を反映する。
- [ ] response request IDとsanitized structured logが一致し、token/password/cookieがない。
- [ ] QA pre-migration DB dump、Media archive/manifest、SHA-256、rollback対象releaseがStage A報告どおり存在する。
- [ ] backup failureは非0終了し、設定root外をretention削除しない。GC/retention dry-runを確認する。

## 7. i18n / CSV（WU-30 / KAN-60）

- [ ] URL parameterなしで日本語、`?lang=en`で英語になり、明示langがbrowser言語より優先される。
- [ ] English未入力値が日本語へfallbackし、unsupported langも日本語へfallbackする。
- [ ] Map/Spot/Category/field label/custom text翻訳を保存し、number/url/boolean値がlocale共有であることを確認する。
- [ ] 既存日本語CSVがそのまま動き、`name[en]`等とcustom field IDの`[en]`列をexport/importできる。不正locale suffixは拒否される。

## 8. Media（WU-31 / KAN-64）

- [ ] 新規画像にoriginalとthumb/display/large/xlarge（upscaleなし）が作成され、alpha画像の見た目が保たれる。
- [ ] backfill再実行が既存valid variantを再生成しない。variant failureでもoriginalが残る。
- [ ] Spot/Category/PIN/logo/Decoration/Floorが適切な最小variantを使い、Floor詳細が不当に縮小されない。
- [ ] `media:gc`既定dry-run、7日grace、明示delete、shared/pending revision参照保護を確認する。

## 9. Snapshot / Publish / Rollback（WU-32 / KAN-57）

- [ ] publish後のpublic viewerがcurrent Snapshotを表示し、通常表示がlive Prisma fallbackに依存しない。
- [ ] unpublished/unpositioned/internal field/pending revision/member/audit/private Media inventoryがSnapshotへない。
- [ ] publish途中の意図的failureで旧current releaseが維持される。
- [ ] 過去READY releaseへのrollbackで内容が戻り、release object自体は書き換わらない。
- [ ] release assetはimmutable cache、`current.json`はrevalidate/no-cacheで、original detach後も旧release画像が表示される。

## 10. Analytics（WU-33 / KAN-55）

- [ ] public loadでMAP_VIEWがsession中1回、Spot detailを意図的に開くとSPOT_VIEWが記録される。
- [ ] admin previewではcountされず、analytics失敗でもpublic UIが待たない。
- [ ] dashboardの日次Map views、合計、Top Spots、期間が更新される。OWNER/割当Editor以外は読めない。
- [ ] raw IP、cookie visitor ID、fingerprint、raw event rowが保存されない。

## 11. SEO / Legal（WU-34 KAN-62 / WU-35 KAN-63）

- [ ] Snapshot由来title/description/canonical/OGP/X card/imageを確認する。overrideとfallbackを比較する。
- [ ] ja canonical、en `?lang=en` canonical、ja/en/x-default hreflangが正しい。
- [ ] unpublished Mapはnoindexかつsitemap外で、private fieldがmetadataへない。
- [ ] `/terms`、`/privacy`、version/effective date/contactが表示され、public footer/login/signupから到達できる。

## 12. Accessibility（WU-36 / KAN-61）

- [ ] keyboardだけでlocale、Floor、Category、Spot一覧、marker、Bottom Sheet、link、Map controlを操作できる。
- [ ] Spot一覧から全公開Spotへ到達でき、Bottom Sheet open時focus移動、Tab trap、Escape close、triggerへのfocus returnが働く。
- [ ] icon button/name/form label/alt/decorative image semanticsをscreen readerで確認する。
- [ ] focus indicator、selected/errorの非color手掛かり、主要contrastを確認する。
- [ ] automated axe対象状態にcritical/serious violationがないことをStage A結果と照合する。

## 13. PDF（WU-37 / KAN-59）

- [ ] A4/A3 × portrait/landscapeを開き、用紙寸法、余白、300-DPI地図、title/logo/PIN/番号/Decoration/legendを確認する。
- [ ] selected Floorとall Floorsを比較し、長いlegendが継続ページへ流れる。
- [ ] 公開Map QRがStage Aの固定public URLと一致する。
- [ ] 未公開Mapは`未公開プレビュー`表示で、存在しないpublic releaseへのQRがない。
- [ ] OWNER/割当Map EDITORだけがexportできる。

## 14. Self-service Onboarding（WU-38 / KAN-70）

- [ ] email/password/organization/current Terms+Privacy同意でpending signupだけが作られ、verification前はTenantへアクセスできない。
- [ ] verification後にUser/Tenant/OWNER/legal acceptanceが作成され、初期Map作成へ遷移する。Mapは自動公開されない。
- [ ] expired/used token、rate limit、resend limit、generic responseを確認する。
- [ ] 既存Userはpasswordを上書きされず、loginと再同意後に別Tenant OWNERとなる。
- [ ] 同じemailのpending組織招待は自動consumeされず、後で対象Tenantへacceptできる。

## 15. URL / Host / TLS（WU-39 / KAN-68）

- [ ] public link、QR、canonical/OGP/sitemapが`PUBLIC_BASE_URL`を使う。
- [ ] invite/reset/signup verificationが`ADMIN_BASE_URL`を使う。
- [ ] production configがHTTP/localhost/Quick Tunnelを拒否し、trusted host/origin外を拒否する。
- [ ] proxy経由HTTPSでredirect loopがなく、外部HTTPはHTTPSへ移る。
- [ ] QAでは既存Quick Tunnel URLを維持し、生成metadataに設定外のtransient URLが混入しない。
